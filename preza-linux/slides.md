# Что такое Linux
Семейство Unix-подобных ОС

- Ядро с открытым исходным кодом (github.com/torvalds/linux)
- Сообщество разработчиков, Линус Торвальдс -- в корне
- Строится вокруг идеи свободного ПО

<div grid="~ cols-2 gap-4" m-t="2">
<div>

### Плюсы открытости

- Всё, что можно придумать, кто-то уже сделал
- Популярное ПО очень стабильно
- Пользователи видят код и правят баги

</div>
<div>

### Минусы открытости

- Непопулярное ПО может быть плохим
- Часто пишется новичками без опыта
- Нет единых стандартов на архитектуру

</div>
</div>

---

# Где применяется Linux

<div grid="~ cols-2 gap-4">
<div>

- **Серверная ОС** -- лидер с огромным отрывом
- **Встроенные устройства** -- открытость, модульность
- **Профессиональная разработка** -- зрелый инструментарий
- **Enterprise, веб, облака** -- близость к production-окружению

</div>
<div>

### Почему не весь мир на Linux?

- Слабая поддержка аппаратуры (драйверы, мониторы)
- Игры: DirectX, не все работают
- Современные дистрибутивы уже дружелюбны

</div>
</div>

# Что такое дистрибутив
Готовая к использованию система

Ядро само по себе не имеет пользовательского интерфейса.

Дистрибутив = ядро + шелл + утилиты + графическая оболочка + пакетный менеджер + конфигурация + политика обновлений

---

# Популярные дистрибутивы

<div grid="~ cols-2 gap-4" m-t="-2">
<div>

- **Ubuntu** -- десктопный "по умолчанию", обновления раз в полгода
- **Fedora** -- от Red Hat/IBM, не любит проприетарное ПО
- **Debian** -- старейший (1993), база для Ubuntu/Mint/SteamOS
- **Arch** -- частые обновления, для опытных

</div>
<div>

- **Mint** -- на базе Ubuntu, свой рабочий стол
- **Gentoo** -- всё из исходников (для фанатов)
- **Альт, РОСА, Астра, РЕД ОС** -- российские, платные/бесплатные
- Сотни дистрибутивов в целом

</div>
</div>

# Чем Linux хорош для программистов

- **Бесплатность** -- виртуальные машины, контейнеры без лицензий
- **Конфигурируемость** -- от 5 МБ до полной системы, сборка под архитектуру
- **Удобство** -- пакетный менеджер, одна команда на установку
- **Консоль** -- вылизана, мощная, shells как язык программирования

<br>

Также инструменты, которых нет в Windows: **Valgrind**, **QEMU**, **Gem5**

# История Linux

<br>

```
Unix (1970-е, DEC мэйнфреймы)
 ├── BSD (Berkeley Software Distribution)
 │    └── Mac OS
 └── Minix (учебная ОС, Танненбаум)
      └── Linux (1990, Торвальдс, студенческая работа)
```

<br>

Windows идёт от MS-DOS → CP/M (1974) -- нет связи с Unix

# Отличия от Windows

<div grid="~ cols-2 gap-4">
<div>

### Файловая система

- Регистр значим: `a.txt` ≠ `A.txt`
- Нет атрибута "скрытый" -- точки в начале имени
- Нет дисков -- один корень `/`
- Монтирование внешних ФС в поддиректории
- Слеши прямые `/`, не обратные

</div>
<div>

### Настройки

- Нет реестра -- всё текстовые файлы
- Конфиги человекочитаемы
- Много опций → папка `<имя>.d` с нумерованными файлами

### Запуск программ

- PATH, не текущая директория (безопасность)
- `./program` для запуска из текущей папки
- Атрибут "исполнимый" (`chmod +x`)

</div>
</div>

# Пакетная система
Основа дистрибутива

<br>

**Пакет** = бинарники + конфиги + документация + метаинформация (имя, версия, зависимости)

Форматы: `.deb` (Debian/Ubuntu) и `.rpm` (Red Hat/Fedora)

Утилиты: `dpkg`, `rpm` (низкоуровневые)

---

# Пакетные менеджеры
Высокоуровневая работа с пакетами

<br>

- **apt** -- Debian, Ubuntu, Mint, Альт
- **yum** -- старая Fedora
- **dnf** -- новая Fedora, РОСА

<br>

Новые подходы (без dependency hell):
**Flatpak**, **Snappy**, **AppImage** -- приложение целиком со всеми зависимостями

---

# Среды рабочего стола
Что видит пользователь

<br>

Графический сервер: **X Server** (старый) или **Wayland** (новый)

<br>

- **GNOME** (GTK+) -- лёгкий, быстрый, не конфигурируемый. Ubuntu, Mint
- **Plasma/KDE** (Qt) -- конфигурируемый, красивый, близок к Windows. РОСА, KUbuntu
- **XFCE** -- ультралегковесный, для слабых машин/серверов

<br>

⚠️ Установка "неродного" приложения притянет пакеты целой среды

# Пользователи и root
Кто имеет права

<br>

**root** -- суперпользователь, может ВСЁ (удалить систему, сломать права, поставить пакеты)

<br>

```bash
whoami              # текущий пользователь
id                  # UID, GID, группы
sudo <команда>      # выполнить от имени root
```

<br>

Не логиниться как root по умолчанию: одна ошибка = повреждение системы

`sudo` -- временно получить права root для одной команды (запросит пароль)

# Wildcards (глобы)
Шаблоны имён файлов

<br>

| Шаблон | Значение |
|--------|----------|
| `*` | Любое количество любых символов |
| `?` | Ровно один любой символ |
| `[1-8]` | Одна цифра от 1 до 8 |
| `[!a-z]` | Не строчная буква |

<br>

```bash
rm -rf *.txt          # удалить все .txt
find . -name "*.csproj"
```

Раскрываются **до** вызова команды

# Переменные окружения и кавычки

<br>

```bash
export PATH=$PATH:/home/user/.dotnet   # добавить в PATH
```

Переменные в `.bashrc` (сессия) или `/etc/profile` (все пользователи)

<br>

### Квотирование

| Тип | Кавычки | Переменные | Wildcards |
|-----|---------|-----------|-----------|
| Сильное | `'text'` | не раскрываются | не раскрываются |
| Слабое | `"text"` | раскрываются | не раскрываются |

```bash
echo '$PATH'    # выведет: $PATH
echo "$PATH"    # выведет содержимое PATH
echo "*.tex"    # выведет: *.tex
```

# Файловая система: inodes

<br>

**inode** (индексный дескриптор) -- запись с метаинформацией: права, расположение на диске

Имя файла = **ссылка** на inode

```bash
ls -i    # показать номера inodes
```

<br>

**Жёсткая ссылка** -- два имени указывают на один inode
- Удаление -- когда ссылок на inode нет (как GC)
- Ссылки на директории невозможны

**Символьная ссылка** (ярлык) -- файл с путём
- Работает через ФС, на директории
- Аналог `.lnk` файлов в Windows

# Настройка системы
Настройка = правка текстового файла

<br>

```bash
hostname                    # имя машины
hostnamectl set-hostname my-pc  # поменять имя
cat /etc/hostname           # где хранится
```

<br>

```bash
echo $PS1                   # текущий приглашение шелла
echo 'PS1="\u@\h:\w\$ "' >> ~/.bashrc   # поменять
source ~/.bashrc            # применить
```

<br>

Ключевая идея: никакого реестра -- всё лежит в `/etc/` (глобально) или `~/` (пользователь), редактируется текстовым редактором

---

# Права доступа

<br>

Три группы по три бита: **r**ead, **w**rite, e**x**ecute

| | Владелец | Группа | Все |
|--|---------|-------|-----|
| rwx | rwx | rwx | rwx |

```bash
chmod +x file.txt    # сделать исполняемым
ls -l                # показать права (rw-r--r-- → 644)
```

Без атрибута Execute файл **нельзя запустить** -- даже скрипт или бинарник

Права директорий: можно иметь право писать файлы (зная имя), но не читать список файлов

---

# Виртуальные файлы

<br>

Философия: всё, что поддерживает потоковый ввод-вывод = **файл**

<br>

| Файл | Назначение |
|------|-----------|
| `/dev/null` | EOF, уничтожает записанные данные |
| `/dev/random` | Бесконечная последовательность случайных чисел |
| `/proc/cpuinfo` | Информация о процессоре |
| `/proc/<pid>/` | Информация/управление процессом |

<br>

Датчики роботов, метрики системы -- тоже файлы в ФС

---

# FHS: Filesystem Hierarchy Standard

<br>

Классификация: **статичные/изменяемые** × **разделяемые/неразделяемые**

Корневая ФС (`/`) -- только самое необходимое для загрузки

Современные дистрибутивы: "joined root" (нарушает FHS, `/bin` → `/usr/bin`)

# Перенаправление и пайпы

<br>

```bash
echo "Hello" > out.txt     # перезаписать файл
echo "World" >> out.txt    # добавить в конец

cat file.txt | sort | uniq | wc -l   # конвейер
```

<br>

**Linux way** -- много мелких программок + шелл с пайпами = сложные сценарии в одну строку

Шелл -- полноценный язык программирования

# systemd: сервисы
Программы, которые работают в фоне

<br>

```bash
systemctl status sshd         # работает ли SSH-сервер?
systemctl start sshd          # запустить
systemctl stop sshd           # остановить
systemctl restart sshd        # перезапустить
systemctl enable sshd         # автозапуск при загрузке
```

<br>

```bash
journalctl -u sshd            # логи сервиса
journalctl -u sshd --since today  # логи за сегодня
```

<br>

Сервисы: `sshd`, `nginx`, `cron`, `NetworkManager` -- фоновые демонны

# Vim

Полноценный интерактивный редактор в консоли

<br>

| Действие | Клавиши |
|----------|---------|
| Режим ввода | `i` |
| Выход из режима ввода | `Esc` |

| Выйти без сохранения | `:q!` |

<br>

- Есть плагины, можно как IDE
- Единственный выход, когда нет GUI (сервер, авария)
- Обязательно освоить хотя бы базово

# Сеть: самое основное
Проверить связь и скачать данные

<br>

```bash
ping 8.8.8.8          # есть ли связь (Ctrl-C для остановки)
ping google.com       # работает ли DNS
```

```bash
curl https://example.com     # показать страницу в консоли
wget https://example.com/f   # скачать файл
```

<br>

Подробнее: TCP/IP, DNS, интерфейсы, маршрутизация -- отдельная большая тема

# Диски и место
Сколько свободного места

<br>

```bash
df -h                # использовано/свободно по разделам
du -sh *             # сколько занимает каждая папка
du -sh /var/log      # а если логи жрут место?
```

<br>

`-h` = human-readable (КБ, МБ, ГБ вместо байтов)

<br>

Типичная проблема: «диск полон» → `df -h` → `du -sh /*` → найти виновника

# Ещё полезное в консоли

<br>

- **Tab** -- автодополнение (в контексте). Дважды -- список вариантов
- **`~`** -- домашняя директория (`cat ~/.bashrc`)
- **`alias`** -- синонимы команд (`alias gcc="gcc -Wall"`)
- **Midnight Commander** -- консольный файловый менеджер
- **Ctrl-R** -- поиск по истории команд
- **Ctrl-W** удалить слово, **Ctrl-U** до начала, **Ctrl-K** до конца
- **Ctrl-A / Ctrl-E** -- начало/конец строки
- **Выделение мышкой + средний клик** -- вставка (не через буфер!)
- **Ctrl-Alt-F1..F6** -- переключение на текстовые терминалы
